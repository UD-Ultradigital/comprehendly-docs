Quickstart

Use this path when you want to prove the integration end to end: exchange a publishable key, load a published page, fill a shared store, and save a submission.

Prerequisites

  • A Comprehendly tenant with at least one published form page.
  • A publishable key (pk_test_… or pk_live_…).
  • An allowlisted origin for the client you are testing.

1. Exchange a publishable key

Exchange happens once per client session. Browsers send Origin automatically; native clients must send the same allowlisted origin explicitly. 

POST https://api.stepcare.app/functions/v1/integration_exchange
{
  "key": "pk_test_…",
  "audience": "stepcare-embed",
  "requested_scopes": [
    "forms.schemas:read",
    "forms.submissions:read",
    "forms.submissions:write"
  ]
}

2. Load a published page

Call gateway operation forms.catalog.list (or SDK helper catalog.list()) if you need to discover a page id, then call gateway operation forms.page.get (or SDK helper page.get(pageId)). Loading a page gives you the current element graph and refreshes the element.id → field_name mapping.

3. Pick one surface

Surface When to use it
Generated FormView You need the SDK to render primitive controls from the page definition.
Bind existing fields You already have DOM or native controls and want Comprehendly to share values with them.

Use generated UI or bind. Do not add a second Comprehendly overlay over host widgets.

4. Fill and save

Whether values came from generated controls, bound controls, or voice, save with forms.submissions.save using field_name-keyed values.

Where to go next

  • Authentication for exchange and allowlist details.
  • Render a form for generated UI.
  • Bind existing fields for host-side controls.
  • Save a submission for the final persistence call.
