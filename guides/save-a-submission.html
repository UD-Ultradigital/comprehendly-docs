Save a submission

Use case: your generated, bound, or voice-assisted flow has collected values and you now want to persist them as a submission.

Prerequisites

  • A page already loaded with page.get.
  • A shared FieldStore containing current values.
  • forms.submissions:write on the exchanged token.

JavaScript

import { Comprehendly } from '../src/index.js'

const client = new Comprehendly({ publishableKey: 'pk_test_…' })
await client.exchange()
await client.page.get('00000000-0000-0000-0000-000000000000')

const fieldValues = client.store.values()

await client.exchange()

const submission = await client.submissions.save({
  pageId: '00000000-0000-0000-0000-000000000000',
  fieldValues
})

console.log('Saved submission', submission.id)

Swift

import ComprehendlyForms

let client = ComprehendlyClient(publishableKey: "pk_test_…")
try await client.exchange()
_ = try await client.pageGet("00000000-0000-0000-0000-000000000000")

try await client.exchange()

let submission = try await client.submissionsSave(
  pageId: "00000000-0000-0000-0000-000000000000",
  fieldValues: client.store.values()
)

print("Saved submission \(submission.id)")

Exchange tokens are short-lived. If a user can spend a while filling the form, refresh the token again right before calling save.

Limits

  • Save payloads are keyed by field_name. Never transform them back to labels.
  • If you bind host widgets, resolve through element.id during editing and let the store emit the correct field_name payload.
  • Voice capture can update the same store first, but saving is still an explicit gateway call unless the hosted flow saves on your behalf.
