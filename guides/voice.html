Fill with voice

Use case: you want microphone capture to write into the same FieldStore used by your generated or bound form surface.

Prerequisites

  • A published page already loaded into the client store.
  • A working exchange token with the same allowlisted origin as the host app.
  • Permission to capture microphone input in the browser or native WebView.

JavaScript

import { Comprehendly, mountVoiceBridge } from '../src/index.js'

const client = new Comprehendly({ publishableKey: 'pk_test_…' })
await client.exchange()
await client.page.get('00000000-0000-0000-0000-000000000000')

mountVoiceBridge('#voice', {
  token: client.accessToken,
  pageId: '00000000-0000-0000-0000-000000000000',
  mode: 'assistant',
  store: client.store
})

window.addEventListener('message', (event) => {
  if (event.data?.type === 'stepcare:fields_updated') {
    console.log('Field values updated from voice', event.data.field_values)
  }
})

Swift

import ComprehendlyForms

let client = ComprehendlyClient(publishableKey: "pk_test_…")
try await client.exchange()
_ = try await client.pageGet("00000000-0000-0000-0000-000000000000")

let voiceURL = try client.voiceBridgeURL(
  pageId: "00000000-0000-0000-0000-000000000000",
  mode: "assistant"
)

VoiceBridgeView(url: voiceURL, store: client.store)

Limits

  • Do not reimplement the Realtime client in v1. Keep voice on the hosted voice-bridge.html / forms fill embed.
  • Forms embed v1.3 posts stepcare:fields_updated; use that event to hydrate host UI if needed.
  • Voice updates the shared store, but save still happens through forms.submissions.save with field_name-keyed values.
