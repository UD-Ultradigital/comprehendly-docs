Bind existing fields

Use case: your app already owns the UI and you want Comprehendly values to stay in sync with your existing DOM or native controls.

Prerequisites

  • A published page loaded with page.get.
  • A stable place to persist each Comprehendly element.id alongside your host control.
  • An agreement that save still uses field_name, not labels.

JavaScript

import { Comprehendly } from '../src/index.js'

const client = new Comprehendly({ publishableKey: 'pk_test_…' })
await client.exchange()
await client.page.get('00000000-0000-0000-0000-000000000000')

const moodInput = document.querySelector('[data-element-id="el-mood"]')

client.store.bind({ elementId: 'el-mood' }, (value) => {
  moodInput.value = value ?? ''
})

moodInput.addEventListener('input', () => {
  client.store.set({
    elementId: 'el-mood',
    value: moodInput.value,
    source: 'bind'
  })
})

Swift

import ComprehendlyForms

let client = ComprehendlyClient(publishableKey: "pk_test_…")
var mood = ""

try await client.exchange()
_ = try await client.pageGet("00000000-0000-0000-0000-000000000000")

try client.store.bind(elementId: "el-mood") { value in
  mood = value as? String ?? ""
}

try client.store.set(elementId: "el-mood", value: mood, source: "bind")

Limits

  • Bind with element.id so page refreshes can resolve the current field_name safely.
  • Do not add generated controls on top of the same host field. Use one surface per field.
  • Unmapped fields can still receive voice updates in the store. Render them separately or ignore them intentionally.
