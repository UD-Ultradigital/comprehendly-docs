Authentication

Comprehendly client SDKs use a publishable key plus an exchange step to mint a short-lived integration token. They do not send a user JWT to the Forms gateway.

Requirements

  1. Create a publishable key in the Comprehendly app.
  2. Allowlist the exact client origin on that key.
  3. Request the scopes your flow needs at exchange time.

Origin allowlist

The allowlist entry must match the runtime Origin exactly: scheme, host, and port only. Common values are http://localhost:4173 for the JavaScript demo and https://ios-demo.comprehendly.nz for the default Swift client.

Browsers set Origin automatically. Native clients must set it explicitly and keep the header value in sync with the publishable key allowlist.

Exchange request

POST https://api.stepcare.app/functions/v1/integration_exchange

{
  "key": "pk_test_…",
  "audience": "stepcare-embed",
  "requested_scopes": [
    "forms.schemas:read",
    "forms.submissions:read",
    "forms.submissions:write"
  ]
}

Send the platform anon key in apikey and Authorization: Bearer headers. A successful exchange returns access_token, expires_in, tenant_id, and granted scopes.

Gateway request

POST https://api.stepcare.app/functions/v1/integration_gateway

{
  "access_token": "scist_…",
  "operation": "forms.page.get",
  "params": {
    "page_id": "00000000-0000-0000-0000-000000000000"
  }
}

Gateway success responses use { "data": ..., "request_id": "uuid" }. SDK helpers unwrap data.

Scope checklist

Scope Needed for
forms.schemas:read Catalog, page load, and field metadata used by generated or bound surfaces.
forms.submissions:read Reading previously saved submissions.
forms.submissions:write Saving a submission from current field values.
