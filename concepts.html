Concepts

Page vs submission

A form is a published page (page_type = form) identified by page_id (UUID). Fill creates a submission (child page) whose values are keyed by field_name.

Field identity

Key Stable? Use
element.id Yes (page node) Preferred bind key for host widgets
data.field_name Can change if authors rename Voice tools, submission payload, store.get
Label Display only Do not match or bind on label

After each page.get, resolve element.id → current field_name. The store does this internally when you bind({ elementId }).

FieldStore

One store per fill session. page.get loads fillable elements. set / voice patches / host edits all merge into the same map.

Fillable element types: form_field, form_field_rating, form_field_score.

Generated UI in v1 implements form_field input types: text, textarea, number, date, boolean, select, multiselect. Layout nodes (headings, columns, media) are ignored. The SDK does not clone page layout.

Generated vs bound

Surface Who draws the control When
Generated (FormView) SDK You do not already have a form UI
Bound Your app Existing or heavily styled widgets. Map element.id → control.

Do not overlay Comprehendly chrome on host widgets. Unmapped fields still live in the store; show them separately or drop them.

Voice modes

session_mode Behaviour
silent (default) Mic capture, no spoken assistant
assistant Spoken walkthrough of the same page

Mint is forms.voice.start. The talker is hosted Realtime, not a platform speech API. Native apps should load the WebView bridge; do not reimplement the Realtime client in v1.
